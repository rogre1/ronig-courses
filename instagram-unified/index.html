ל-Claude שקורא את המדריך

  • הקובץ SETUP.md שבתבנית הוא המקור הראשי, כולל הנספח Unified login בסופו. המדריך הזה משלים אותו לפי הקמה שעבדה, ומוסיף את מה שלא כתוב שם.
  • עובדים לפי הסדר. אחרי כל צעד שהמשתמש עושה, מחכים שיכתוב "עשיתי" לפני שממשיכים.
  • אומרים בדיוק על מה ללחוץ, בעברית פשוטה. אם המשתמש לא מוצא משהו, שואלים מה הוא רואה במסך.
  • לא מבקשים להדביק בצ'אט סיסמאות, קודים או מפתחות. ה-App secret מודבק בטרמינל מוסתר (צעד 18), וה-VERIFY_TOKEN נקרא מקובץ מקומי.
  • לפני פעולה שמשנה משהו בחשבון של המשתמש (העלאה, מעבר ל-Live) מסבירים מה היא עושה ומקבלים אישור.
  • צעד שמסומן "בכרום": אם Claude in Chrome מחובר, Claude לוחץ בעצמו. אחרת מדריכים את המשתמש ללחוץ על אותם כפתורים.
  • כשמשהו נתקע, מחפשים קודם בסעיף התקלות המוכרות.
אתם לוחצים או מקלידים בעצמכם Claude מריץ פקודה או לוחץ בכרום לבד המערכת עושה את זה לבד

מה קורה כשמישהו כותב את המילה

כל צעד בהקמה מחבר עוד חוליה בשרשרת הזו

  1. מישהו כותב את מילת המפתח בתגובה לפוסט או לריל, בתגובה לסטורי או בהודעה ישירה.
  2. מטא שולחת התראה לכתובת /webhook של המערכת ב-Cloudflare.
  3. בדיקת חתימה: המערכת מוודאת עם ה-App secret שההתראה באמת הגיעה ממטא, ועונה לה מיד.
  4. התאמה לחוק: מחפשת חוק פעיל עם אותה מילה ואותו פוסט. אין התאמה? לא קורה כלום ולא נרשם כלום.
  5. תור: כל אירוע נשמר פעם אחת בלבד, כך שגם אם מטא שולחת אותו פעמיים, יוצאת הודעה אחת.
  6. שליחה: הודעה פרטית עם כפתור וקישור, דרך הממשק הרשמי של אינסטגרם. ואם הוגדרה, גם תגובה פומבית קצרה.
  7. רישום: כל שליחה מופיעה ב"פעילות אחרונה" בדף הניהול, כולל שגיאות.
  • כל 5 דקות תזמון קבוע שולח את מה שנשאר בתור.
  • עד 150 הודעות בשעה (MAX_PER_HOUR).
  • לא עונה לעצמו: תגובות של החשבון העסקי עצמו לא מקבלות הודעה.
  • אין חוק, אין הודעה: שום הודעה לא יוצאת עד שיש חוק פעיל.
1

הכנה במחשב

צעדים 1 עד 4 · שום דבר עוד לא עולה לאינטרנט

  1. 1הורדת התבנית Claude

    Claude מוריד את התבנית לתיקייה מקומית וקורא את SETUP.md עד הסוף, כולל הנספח.

    git clone https://github.com/rogre1/instagram-dm-template

  2. 2התקנה ובדיקות Claude

    מריץ npm install ואחר כך npm test. כל הבדיקות צריכות לעבור לפני שממשיכים.

  3. 3שם ומייל לעמוד הפרטיות אתםClaude

    אתם נותנים את שם העסק ומייל ליצירת קשר. Claude כותב אותם בקובץ wrangler.toml, בשדות BRAND_NAME ו-CONTACT_EMAIL.

    למה: הם מופיעים בעמוד הפרטיות ובעמוד מחיקת הנתונים, ומטא דורשת את שניהם.

  4. 4שני קודים סודיים Claude

    • VERIFY_TOKEN: מטא משתמשת בו כדי לוודא שכתובת ה-Webhook שייכת לכם.
    • ADMIN_PASSWORD: הסיסמה של דף הניהול.

    שניהם נשמרים בקובץ מקומי (למשל secrets.local.txt) שרשום ב-.gitignore, ולא מודבקים בצ'אט.

2

השרת ב-Cloudflare

צעדים 5 עד 11 · אתר קיים, דומיין ו-DNS לא משתנים

  1. 5חיבור ל-Cloudflare בהרשאות מצומצמות Claudeאתם

    Claude מריץ התחברות עם רשימת הרשאות מפורשת. בדפדפן נפתח מסך של Cloudflare. בודקים שמופיעות בו רק ההרשאות האלה, ולוחצים Allow:

    npx wrangler login --scopes account:read user:read workers_scripts:write workers_tail:read d1:write

    בלי הרשאות ל-DNS, לדומיינים או ל-SSL. ההרשאה offline_access נוספת לבד. אם נפתח מסך עם רשימה ארוכה יותר, סוגרים אותו בלי לאשר.

  2. 6מסד נתונים Claude

    יוצר מסד D1, מעתיק את ה-database_id שחוזר לקובץ wrangler.toml, ומריץ את קובץ הטבלאות.

    npx wrangler d1 create instagram-dm
npx wrangler d1 execute instagram-dm --remote --file=src/schema.sql

  3. 7שם לכתובת workers.dev אתםClaude

    בוחרים שם קצר באנגלית, אותיות ומספרים בלי נקודות. הכתובת תהיה instagram-dm.NAME.workers.dev, ומעכשיו נקרא לה "כתובת ה-Worker".

  4. 8אימות המייל של Cloudflare אתם

    Cloudflare לא מאפשרת העלאה ראשונה לפני שהמייל של החשבון מאומת. לוחצים על הקישור במייל מ-Cloudflare.

  5. 9העלאת המערכת Claude

    מריץ npx wrangler deploy. ה-Worker עולה לכתובת שלו, עם תזמון שרץ כל 5 דקות.

  6. 10שמירת הקודים כסודות Claude

    שומר את VERIFY_TOKEN ואת ADMIN_PASSWORD כסודות של ה-Worker עם npx wrangler secret put. הערכים עוברים מהקובץ המקומי ישר ל-Cloudflare, בלי להופיע במסך.

  7. 11בדיקה ראשונה של הכתובות Claude

    • /privacy פתוח לכולם (200)
    • /data-deletion פתוח לכולם (200)
    • /admin נעול בסיסמה (401)
    • /webhook חוסם בלי הקוד הפנימי (403)
3

אפליקציה במטא

צעדים 12 עד 22 · את רוב הלחיצות Claude יכול לעשות בכרום, את הקודים הסודיים אתם מדביקים

  1. 12יצירת האפליקציה אתם

    • ב-developers.facebook.com: למעלה My Apps, ואז Create App. בפעם הראשונה מטא מבקשת להירשם כמפתח.
    • App name: שם לבחירה. מטא לא מאשרת שם שכולל את המילה Instagram.
    • App contact email: המייל שלכם.
    • ב-Use cases בוחרים Manage messaging & content on Instagram.
    • במסך Business בוחרים את התיק העסקי (Business portfolio) שחשבון האינסטגרם נמצא בו.
    • בסוף Create app. ההודעה שלא זוהו דרישות תקינה.

    תנאי מוקדם: חשבון אינסטגרם מקצועי (עסקי או יוצר) בתוך תיק עסקי של מטא. עמוד פייסבוק לא נדרש.

  2. 13איזה מסלול התחברות מטא מציעה? Claude

    Use cases → Customize (ליד Manage messaging & content on Instagram)

    • אם מופיע API setup with Instagram login: ממשיכים במסלול הרגיל שב-SETUP.md. הצעדים כאן לא נדרשים.
    • אם יש רק API setup with Unified login ומופיעה ההודעה is not available for newer apps: זה תקין. מסוף אוקטובר 2026 זה המצב בכל אפליקציה חדשה, והצעדים הבאים מתארים את המסלול הזה.

  3. 14שלוש הרשאות Claude

    Use cases → Customize → Permissions, ולוחצים Add ליד כל אחת: instagram_basic, instagram_manage_comments, instagram_manage_messages.

    למה קודם: בלי זה רשימת ההרשאות במסך יצירת הקונפיגורציה ריקה.

  4. 15קונפיגורציית התחברות ידנית Claude

    API setup with Unified login → Create configuration

    • שם: לבחירה
    • Login variation: General
    • סוג טוקן: System-user access token
    • תוקף: Never
    • נכסים: רק Instagram accounts, מסומן Asset required
    • הרשאות: רק שלוש ההרשאות מהצעד הקודם

    בסוף Create. מטא מציגה Configuration ID, ו-Claude שומר אותו.

    למה לא התבנית המוכנה של מטא: היא מוסיפה הרשאות פרסום (ads_management, ads_read) וגישה לחשבונות מודעות, שהמערכת לא צריכה.

  5. 16כתובת חזרה אחרי ההתחברות Claude

    API setup with Unified login → Redirect URL → Register a new redirect URL

    כותבים את כתובת ה-Worker ואחריה /callback, ולוחצים Save.

  6. 17התאמת הקוד ל-Unified login Claude

    התבנית נכתבה למסלול הרגיל, ולכן Claude מתאים כמה פונקציות (הקוד המלא בערכים וקוד). מוסיף ל-wrangler.toml את AUTH_MODE במצב unified, את FB_CONFIG_ID ואת GRAPH_VERSION. שומר את ה-App ID (מ-App settings → Basic) כסוד IG_APP_ID, ומעלה מחדש.

  7. 18הקוד הסודי של האפליקציה אתםClaude

    App settings → Basic → App secret → Show

    • מעתיקים את ה-App secret.
    • Claude פותח לשונית טרמינל שמריצה את סקריפט העזר set-app-secret.mjs (הקוד בערכים וקוד).
    • מדביקים פעם אחת ולוחצים Enter. המסך נשאר ריק בכוונה.
    • מופיעה השורה Done. You can close this tab.

    כך הקוד נשמר כסוד IG_APP_SECRET בלי לעבור בצ'אט. באפליקציית Claude למחשב, הטרמינל שלכם לא רואה את ההתחברות ל-Cloudflare שנעשתה מהכלים של Claude, ולכן קודם מריצים בו את פקודת ההתחברות מצעד 5.

  8. 19עמודי פרטיות וקטגוריה Claude

    App settings → Basic

    • Privacy policy URL: כתובת ה-Worker ואחריה /privacy
    • User data deletion: כתובת ה-Worker ואחריה /data-deletion
    • Category: Messenger bots for business

    שומרים עם Save changes. לא צריך למלא כתובת מגורים או משרד.

  9. 20כתובת ה-Webhook Claude

    API setup with Unified login → Configure webhooks

    ב-Callback URL כותבים את כתובת ה-Worker ואחריה /webhook. לשם מטא תשלח כל תגובה והודעה.

  10. 21אימות ה-Webhook אתם

    • פותחים את הקובץ המקומי ומעתיקים את הערך של VERIFY_TOKEN.
    • מדביקים בשדה Verify token ולוחצים Verify and save.
    • את המתג של client certificate משאירים כבוי.

    המתג כבוי כי המערכת כבר בודקת עם ה-App secret שכל התראה הגיעה ממטא.

  11. 22הרשמה לתגובות ולהודעות Claude

    באותו מסך לוחצים Subscribe ליד comments וליד messages. הגרסה צריכה להיות זהה ל-GRAPH_VERSION (בהקמה שנבדקה: v27.0).

    חשוב: כפתור Test במסך הזה שולח התראת בדיקה גם בלי הרשמה. ההרשמה היא מה שמעביר תגובות אמיתיות.

חיבור חשבון האינסטגרם

צעדים 23 עד 25 · החיבור לא שולח שום הודעה

  1. 23כניסה לדף הניהול אתם

    פותחים את כתובת ה-Worker ואחריה /admin. שם משתמש: כל מילה. סיסמה: הערך של ADMIN_PASSWORD מהקובץ המקומי.

  2. 24חיבור אינסטגרם אתם

    • לוחצים על כפתור החיבור בדף הניהול.
    • במסך של מטא בוחרים את התיק העסקי ואת חשבון האינסטגרם, ולוחצים הבא.
    • מאשרים את ההרשאות עד הסוף: קריאת החשבון, תגובות והודעות.
    • חוזרים לדף הניהול, והסטטוס הוא "מחובר".

  3. 25מה קורה ברקע לבד

    • המערכת מחליפה את הקוד שמטא החזירה בטוקן קבוע שלא פג.
    • מאתרת את חשבון האינסטגרם שהוקצה לאפליקציה.
    • רושמת את האפליקציה לתגובות ולהודעות של החשבון: POST /<ig-id>/subscribed_apps עם comments,messages.

    בלי הרישום הזה התראות הבדיקה של מטא עדיין מגיעות, אבל תגובות אמיתיות לא. אם החיבור נכשל, דף השגיאה מציג את ההודעה של מטא.

הפעלה

צעדים 26 עד 27 · שתי הגדרות שבלעדיהן זה לא יעבוד לעוקבים

  1. 26מעבר למצב Live Claudeבאישורכם

    בתפריט הצד של האפליקציה: Publish. הכפתור מתחלף ל-Unpublish, וזה הסימן שהמעבר הצליח.

    במצב פיתוח מטא לא מעבירה תגובות של אנשים שאין להם תפקיד באפליקציה, כלומר של העוקבים. המעבר עצמו לא שולח כלום.

  2. 27Allow access to messages אתם, בטלפון

    בחשבון העסקי, באפליקציית אינסטגרם בטלפון. באתר של אינסטגרם האפשרות לא מופיעה.

    Profile → ☰ → Settings and activity → Messages and story replies → Message controls → Connected tools → Allow access to messages

    בלי זה אינסטגרם חוסם כל שליחה עם השגיאה (#200) The account owner has disabled access to Instagram Direct Messaging Outside of Instagram App.

השינויים במסלול Unified. המסלול הרגיל של התבנית נשאר כמו שהוא, מאחורי הבדיקה unified(env).

const unified = (env) => env.AUTH_MODE === 'unified';
function graph(env, path) {
  const host = unified(env) ? 'https://graph.facebook.com' : 'https://graph.instagram.com';
  return `${host}/${env.GRAPH_VERSION}${path}`;
}

// authorizeUrl, unified branch: no scope, the configuration decides
const u = new URLSearchParams({
  client_id: env.IG_APP_ID,
  config_id: env.FB_CONFIG_ID,
  redirect_uri: redirectUri,
  response_type: 'code',
  override_default_response_type: 'true',
  state,
});
return `https://www.facebook.com/dialog/oauth?${u}`;

// exchangeCode, unified branch: system user token, never expires
const u = new URLSearchParams({
  client_id: env.IG_APP_ID, client_secret: env.IG_APP_SECRET,
  redirect_uri: redirectUri, code,
});
return (await call(graph(env, `/oauth/access_token?${u}`))).access_token;

// getMe, unified branch: find the Instagram account assigned at login
async function getAssignedInstagram(env, token) {
  const profile = async (id) => {
    const p = new URLSearchParams({ fields: 'id,username', access_token: token });
    const ig = await call(graph(env, `/${id}?${p}`));
    return { user_id: ig.id, username: ig.username || '' };
  };
  try {
    const p = new URLSearchParams({ fields: 'id,username', access_token: token });
    const res = await call(graph(env, `/me/assigned_instagram_accounts?${p}`));
    const first = res.data?.[0];
    if (first?.id) return first.username ? { user_id: first.id, username: first.username } : profile(first.id);
  } catch (e) {
    console.error('assigned_instagram_accounts', e.message);
  }
  // fallback: debug_token lists the asset ids granted for each permission
  const d = new URLSearchParams({ input_token: token, access_token: `${env.IG_APP_ID}|${env.IG_APP_SECRET}` });
  const dbg = await call(graph(env, `/debug_token?${d}`));
  const scopes = dbg.data?.granular_scopes || [];
  const ids = (scopes.find((s) => s.scope === 'instagram_basic')
    || scopes.find((s) => s.scope?.startsWith('instagram_')) || {}).target_ids || [];
  if (!ids.length) throw new Error('No Instagram account was granted at login');
  return profile(ids[0]);
}

// subscribe and listMedia: the Instagram account id instead of "me"
export async function subscribe(env, token, igUserId) {
  const target = unified(env) ? igUserId : 'me';
  const p = new URLSearchParams({ subscribed_fields: 'comments,messages', access_token: token });
  return call(graph(env, `/${target}/subscribed_apps?${p}`), { method: 'POST' });
}

שומרים אותו בתיקיית התבנית ומריצים node set-app-secret.mjs בטרמינל שלכם, אחרי התחברות ל-Cloudflare באותו טרמינל.

// Asks for the Meta App secret with hidden input and stores it as IG_APP_SECRET.
// The value is never printed. Uses the existing narrow Cloudflare login.
import { spawn } from 'node:child_process';
import readline from 'node:readline';
import { fileURLToPath } from 'node:url';

const wrangler = fileURLToPath(new URL('./node_modules/wrangler/bin/wrangler.js', import.meta.url));
const rl = readline.createInterface({ input: process.stdin, output: process.stdout, terminal: true });
console.log('Paste the Meta App secret here and press Enter. Nothing will show while you paste.');
rl._writeToOutput = () => {};
rl.question('', (answer) => {
  rl.close();
  process.stdout.write('\n');
  const value = answer.trim();
  if (value.length < 16 || /\s/.test(value)) {
    console.log('This does not look like an App secret. Nothing was saved. Run the command again.');
    process.exit(1);
  }
  const child = spawn(process.execPath, [wrangler, 'secret', 'put', 'IG_APP_SECRET'], {
    cwd: fileURLToPath(new URL('.', import.meta.url)),
    // stdin is a pipe, so wrangler runs non-interactively; CI must stay unset or it ignores the saved login
    env: Object.fromEntries(Object.entries(process.env).filter(([k]) => k !== 'CI')),
    stdio: ['pipe', 'inherit', 'inherit'],
  });
  child.stdin.end(value);
  child.on('exit', (code) => {
    console.log(code === 0 ? 'Done. You can close this tab.' : 'Saving failed. Tell Claude what you see above.');
    process.exit(code ?? 1);
  });
});
